# Case Card: Strategy Planning

Use this case when a broad strategy or planning request contains several stakeholders, uncertain resources, and a real execution horizon.

## Source And Status

- Thread: `019e0dc3-ed4d-7de1-982b-de585d450b7e`
- Initial input: long-running offline event concept, government cooperation, two participant profiles, AY's role and desired outcomes.
- Historical status: `no_final_acceptance`. User turn 4 is `partial_approval` of the framework direction; later corrections continued.

## Before

The first request asked for an overall framework before details. Important unknowns remained: government authority, budget, third-party role, and conversion resources.

## Failure Mechanism

The work repeatedly looked complete before the decision model was sound. It moved too quickly into event modules and generic stakeholder phrases, then forced AY to supply the useful structure: purpose and goal, research, stakeholder supply-demand, phased entry/exit conditions, resources, deliverables, and next actions.

“Concise” was also over-corrected into context-free labels. AY wanted direct language with enough mechanism to make the choice understandable.

## Better Route

1. State the real decision and desired change; separate government, organizer, participant, and AY outcomes.
2. Mark confirmed facts, consequential unknowns, and the minimum research needed before commitment.
3. Map each actor's demand, supply, incentive, dependency, and reason to keep participating.
4. Identify the decisive contradictions, then compare only viable event mechanisms and choose one working route.
5. Translate the route into phases with entry condition, exit condition, core action, required resource, owner or acquisition path, and review point.
6. Match the requested tier. For a “framework first” request, produce a high-density decision map covering why, core actors, decisive questions, proposed modules, comparison logic, and what must be aligned next. Do not fill the operating plan, detailed schedule, or invented commitments until that framework is accepted.

For this kind of first checkpoint, a suitable visible shape is:

- a one-sentence project judgment;
- one strategy map table with `phase and relative timing / question to resolve / entry and exit / mechanism / resource and owner / indicator or output / boundary`;
- one stakeholder value-exchange table with `actor / wants / contributes / mechanism`; and
- no more than a few alignment choices that unlock the next version.

If the answer has become a sequence of fully developed chapters, it has crossed the requested tier even when each chapter is thoughtful.

## Scope And Counterexample

Apply this to ambiguous strategy, product, event, market, or research planning. Do not force the six stages into visible headings for a narrow rewrite or routine implementation task. High information density does not justify inventing budgets, permissions, owners, or commitments.
